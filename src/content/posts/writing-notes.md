这是一篇排版与使用示例，不是作者的真实随笔。正文可以包含普通段落、标题、引用、列表以及代码。

## 写一篇新文章

在 `src/content/posts/` 中新建一个 Markdown 文件。开头的几行写标题、摘要、日期与分类，下面就是正文。使用英文文件名，它也会成为文章网址的一部分。

```yaml
title: '我的第一篇文章'
description: '这篇文章的一句话摘要。'
date: 2026-11-04
category: 随笔
sample: false
```

这里展示的是头部字段。实际文件需要在字段前后各加一行三个短横线，详细示例在 README 中。尚未发布的文章可以设置 `draft: true`，它不会出现在目录或构建出的网页里。

## 为阅读留白

段落之间留一行空白。标题不是装饰，它应该带读者进入一段新的内容。列表适合几个清楚的要点，不必把每句话都变成列表。

> 好的排版并不替文字说话，只是给文字一个合适的声音。

对于技术笔记，代码也是正文的一部分。短代码可以行内书写，较长的代码用代码块保留结构。代码块保留缩进与长行，超出书页宽度时可横向滚动；右上角可复制完整代码。

```js
const notebook = {
  title: 'Unehao 随笔',
  format: 'Markdown',
  output: '静态 HTML'
};
console.log(notebook.title);
```

## 一份小小的清单

| 内容 | 存放位置 |
| --- | --- |
| 文章 | src/content/posts/ |
| 图片 | public/images/ |
| 页面样式 | src/styles/global.css |

图片和字体最好随着站点一起保存。即使未来搬家，也不必担心外部链接失效。本站使用自托管字体，不会向海外字体服务发出请求。

## 以后再做的事情

不必一次把所有功能加进来。等有了几篇真实文章，再看看自己是否需要标签、搜索、评论或新的目录方式。让需求从使用中长出来，比先堆满功能更轻松。
